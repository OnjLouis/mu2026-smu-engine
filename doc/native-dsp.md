# エフェクトを C++ で鳴らす軽量モード（試作）

**既定は切。** 実機の音が要るときは、今までどおり MEG（実機のエフェクト DSP）をそのまま回す。
軽量モードでは、マスタの 4 つの口（リバーブ・コーラス・バリエーション・インサーション 1）を、firmware が
MEG に置いたプログラムと**同じ作りの C++** で鳴らす（下の「MEG と同じ作りのリバーブ」「MEG と同じ作りのエフェクト」）。
実機エミュとの差は、書き出した音の帯ごとの平均で 0.01dB 前後（D.TURNTBL だけ 2.4dB）。
firmware のプログラムが見つからない形のときは、系統ごとの近似（前の試作）で鳴らし、そちらは同じ音にはならない。

```bash
build/render.exe <rom> 曲.mid out.wav 30 --native-fx        # エフェクトだけ C++（MEG も回る）
build/render.exe <rom> 曲.mid out.wav 30 --native-fx-full   # MEG を回さない（いちばん軽い）
build/gui.exe    <rom> --native-fx-full                     # 窓でも同じ
build/live.exe   <rom> --native-fx-full
```

`gui.exe` は**動かしたまま切り替えられる**（窓を右クリック →「エフェクトを C++ で鳴らす」）。
聴き比べはこれが早い。

プラグイン（VST3・CLAP・AU）は `%LOCALAPPDATA%\S-MU2000\plugin.ini` に書く。

```
native_fx=2
```

## 何をしているか

MU2000 のエフェクトは、SWP30 の中の MEG という DSP が 1 サンプルにつき 384 段の命令を回して作る。
軽量モードは、**ミキサから MEG への送りを横取りして、代わりに C++ のエフェクトを鳴らす**。

| 送り | MEG のレジスタ | ミキサの出力 |
|---|---|---|
| リバーブ | m24 / m25 | 10 |
| コーラス | m26 / m27 | 11 |
| バリエーション | m2c / m2d | 14 |
| インサーション 1 | m28 / m29 | 12 |
| 乾いた音 | m20 / m21 | 8 |

この対応は、送りを 0 と 127 にした曲を鳴らしてレジスタを比べ、実測で決めた（`tools` には入れていない
使い捨ての道具で調べた）。インサーション 2-4 はマスタ側の送りに現れないので、まだ手を付けていない。

`--native-fx-full` では、さらに **MEG の 384 段を回さない**。乾いた音（ミキサ出力 8）と C++ の
エフェクトを混ぜ、マスター EQ（5 帯）も C++ で掛けて DAC へ出す。

## 中身

| ファイル | 中身 |
|---|---|
| `src/dsp/util.h` | 遅延の線・1 次と双 2 次のフィルタ・LFO（正弦は表引き）・包絡線を追うもの |
| `src/dsp/reverb.h` | 前遅れ → 初期反射 → 8 本の遅延を Householder 行列で混ぜる網（FDN）。firmware のリバーブのプログラムが見つからないときだけ使う。各段に減衰のローパスとハイパス |
| `src/dsp/meg_reverb.h` | **リバーブ 18 種類を MEG と同じ作りで**（下の「MEG と同じ作りのリバーブ」） |
| `src/dsp/meg_fx.h` | 口ごとに firmware のプログラムの形を見分け、MEG と同じ作りの C++ を選ぶ |
| `src/dsp/meg_fx_common.h` | その C++ が共通で使うもの（飽和・24bit の切り捨て・遅延メモリの番地・表の読み出し） |
| `src/dsp/meg_fx_*.h`・`meg_fx_list.h` | 形ごとの C++（`tools/meg_fx` が作る。手で直さない） |
| `src/dsp/blocks.h` | 初期反射／ゲート・ディレイ・コーラス/フランジャー/フェイザー・回転/トレモロ/パン・歪み・EQ・ワウ・コンプ/ゲート・ローファイ・マスター EQ |
| `src/dsp/blocks2.h` | 形が決まっているもの（リングモジュレータ・スライス・アイソレータ・共振ローパス・真ん中消し・エンハンサ・音程変え・しゃべる響き） |
| `src/dsp/fx_native.h` | 種類（MSB/LSB）から作りを選び、XG のパラメータを渡す |

種類の割り当ては `xg::fx_categories()` の分け方に合わせてある（リバーブ系 → 残響、ディレイ系 → ディレイ、
歪み系 → 歪み…）。パラメータは `xg/fx_params.h` の表を引いて、**表示の値をそのまま物理量として**使う
（`ReverbTime` の `2.1` は 2.1 秒、`LPF Cutoff` の `6.3k` は 6300Hz）。値は `mu2000::native_fx_update()` が
512 サンプルごとにワーク RAM から読み直す。

## MEG と同じ作りのリバーブ（`src/dsp/meg_reverb.h`）

**リバーブの口は、実機と聞き分けられない音で鳴る。** 2026-09-30。

firmware は、リバーブの 18 種類（HALL1/2/M/L・ROOM1/2/3/S/M/L・STAGE1/2・PLATE・GM PLATE・
WHITE ROOM・TUNNEL・CANYON・BASEMENT）の**どれにも同じ形のプログラム**を MEG に置く。
種類とパラメータの違いは、命令ごとの係数と番地表（遅延の長さ）だけ。そこで形を C++ で書き起こし、
係数と番地は firmware が MEG に書いた値をそのまま読む。種類もパラメータも実機どおりに効く。

中身（区画 0 の 156 命令のうち、リバーブの部分）:

* 入口: 送り（m24/m25）に 1 次のハイパスとローパス → 入口の遅延線
* 初期反射: 入口の遅延線から左右 5 タップずつ
* 拡散: 左右のいちばん早いタップを混ぜて 1 次のフィルタ → オールパス 2 段
* 後部: 遅延線 6 本。読んだ音に 2 タップの FIR と 1 極の減衰を掛け、拡散の音と足して書き戻す
* 出口: 初期反射 + 6 本から 1 タップずつ → オールパス 2 段 → ×4 して m24/m25

遅延メモリは MEG と同じ 1 本の環状の窓（64k 語）で、番地も同じ式（番地表の値 − サンプル番号）で引く。
読み書きの対応を決め打ちしないので、遅延の並びが違う PLATE・GM PLATE も同じ結線になる。
区画 0 には マスター EQ と最後の足し合わせも入っているが、そこは今までどおり。

**戻りは MEG と同じ m24/m25 に書く。** 次のサンプルのミキサが、実機と同じ計算で戻りのレベルとパンを掛ける
（前の試作の「戻りの量 0.6」のような実測の合わせ込みが要らない）。

firmware のプログラムがこの形のときだけ使う（区画 0 の 0x00-0x97 の命令語の FNV-1a で見分ける。
MU2000 EX の v2.01 ではリバーブ 18 種類とテストの曲のどれでも同じ値）。形が違えば前の試作（FDN）で鳴らす。

### 実機（MEG）とどれだけ違うか

MEG と並べて毎サンプル同じ送りを入れ、戻り（m24/m25）を比べると、音のあるあいだの差は −42〜−60dB。
違いは MEG の丸め（レジスタの 24bit・遅延メモリの 16bit 浮動小数点・書き込みごとのディザ）だけで、
残響の尾が小さくなるほど比が大きく見える（絶対値では最大 −86dBFS）。

書き出した音（リバーブ送り 127 で C4 を 0.25 秒）を 50ms・オクターブ帯ごとに比べた差の平均（最大）:

| 種類 | 前の試作（FDN、`--native-fx-full`） | MEG と同じ作り（`--native-fx-full`） |
|---|---|---|
| HALL1 | 7.4dB（25.4） | **0.05dB**（0.8） |
| ROOM1 | 4.1dB（17.7） | **0.05dB**（1.1） |
| PLATE | 7.4dB（29.2） | **0.25dB**（3.1） |
| CANYON | 25.4dB（57.5） | **0.11dB**（1.1） |

### 速さ

リバーブ単体で 1 サンプル **46〜59ns**（Ryzen 7 9700X）。MEG ではリバーブの部分だけで約 150ns だった。
MEG をまったく回さない `--native-fx-full` の dense は、1 ブロック 0.91〜0.98ms → 0.78〜0.79ms。

## MEG と同じ作りのエフェクト（`src/dsp/meg_fx*.h`）

2026-09-30。リバーブ（上の節）と同じやり方を、**コーラス・バリエーション・インサーション 1 の全種類**に広げた。
軽量モード（`--native-fx` / `--native-fx-full`）では、マスタの 4 つの口がどれも実機と聞き分けられない音で鳴る。

### 形は 34 通り

firmware は種類ごとに MEG のプログラムを置くが、**同じプログラムを使い回す種類が多い**（係数と番地表だけが違う）。
ROM の種類表（コーラス 21・バリエーション 118）を全部鳴らして命令語を比べると、

| 口 | 種類 | 形 |
|---|---|---|
| リバーブ（区画 0 の 0x00-0x97） | 18 | 1（手で書き起こした `meg_reverb.h`） |
| コーラス（0x98-0xbf） | 20 | 4（17 種類が 1 つの形） |
| バリエーション（区画 3、0x120-0x17f） | 117 | 30（DELAY・CHORUS・FLANGER・THRU など 26 種類が 1 つ、リバーブ系 18 種類が 1 つ…） |
| インサーション 1（区画 2、0xc0-0x11f） | 117 | 30（バリエーションと同じ分かれ方。レジスタと置き場所だけ違う） |

### 書き起こし方（`tools/meg_fx`）

```bash
python tools/meg_fx/rom_types.py          # ROM の種類の表 → build/meg_fx/types.txt
python tools/meg_fx/probe.py              # リバーブ 18 種類を鳴らして MEG を書き出す
python tools/meg_fx/probe2.py cho render  # コーラス（var・ins も同じ）。形の分け方も書き残す
python tools/meg_fx/mkmanifest.py         # バリエーション・インサーションの形の一覧
python tools/meg_fx/build_all.py          # src/dsp/meg_fx_*.h と meg_fx_list.h を作り直す
python tools/meg_fx/vartest.py            # 実機エミュと書き出しを比べる（KIND=ins でインサーション）
```

書き出し（`--dump-meg`）は firmware の中身なので `build/meg_fx` に置き、リポジトリには入れない。

形ごとの C++ は道具で作る（手で直さない）。MEG の決まりをそのまま写す:

* m / r / idx への書き込みは 3 命令あとに入る。遅延メモリへ書く値と読んだ値は 2 命令あと。t の値は 2 命令前の p から
* 番地 = 番地表の値 + idx - サンプル番号（区画の窓で折り返す）。絶対番地の読み出し（bit 0x23）は、firmware が
  遅延メモリの前のほう（0x4000-0x5fff）に置いた表を、SWP30 のリバーブ RAM から直に読む
* 分岐（LO-FI・DYNA 系・V-FLANGER・SLICE）と印（MULTI COMP）のある形は、レジスタを変数として持ち、遅れた書き込みを
  「書くかどうか」の印つきで回す（飛ばされた命令は書かないが、前の命令の遅れた書き込みは入る）
* p の飽和の上限は 2^38 - 1（レジスタに入れると 0x7fffff）。ちょうど 1.0 にすると 24bit の折り返しで -1.0 に化け、
  歪み系が壊れていた。レジスタへ入れるときは MEG と同じく 0 の側へ切り捨てる（積み上げていくレジスタが同じだけ遅れる）

LFO の値は MEG の LFO（`get_lfo`）をそのまま使う。係数と番地は 32 サンプルごとに MEG から読み直す。
鳴らし始めには、MEG のその区画の遅延メモリの中身を写してから始める（切り替えたときに MEG に残っていたもの）。

### 組み込み（`dsp/meg_fx.h`、`swp30.cpp` の軽量モード）

プログラムが変わるたびに、口ごとに命令語の FNV-1a を `meg_fx_list.h` の一覧と照らす。合えばその形の C++ で鳴らし、
戻りは MEG と同じレジスタ（m24/m25・m26/m27・m2c/m2d・m28/m29）に書く。ミキサが戻りのレベル・パン・接続
（SYSTEM / INSERTION）をそのまま掛ける。合わなければ前の試作（系統ごとの近似）で鳴らす。

気をつけたこと:

* **区画の最後の 3 命令で書く戻り**（バリエーションのリバーブなど）は、MEG では次のサンプルの頭（`flush_writes`）で
  入る。軽量モードでも MEG は（送りの無いまま）回っているので、その書き込みを取り消さないと C++ の戻りが消える
* 遅延メモリの窓の長さは地図から求める。命令表は、静まった区画を空の命令に替えていることがある（窓が 1 になって
  C++ のメモリが消えていた）

### 実機（MEG）とどれだけ違うか

種類ごとに C4 を 0.25 秒（送り 127、バリエーションは接続 SYSTEM、インサーションはパート 1）鳴らして書き出し、
50ms・オクターブ帯ごとに比べた差の平均:

| 口 | 種類 | 中央値 | いちばん大きいもの |
|---|---|---|---|
| コーラス | 20 | 0.01dB | 0.03dB（CHORUS 2・CELESTE 2） |
| バリエーション | 117 | 0.01dB | D.TURNTBL 2.4dB、DYNA RING 0.56dB、ほかは 0.35dB 以下 |
| インサーション 1 | 117 | 0.01dB | D.TURNTBL 2.4dB、DYNA RING 0.55dB、SLICE 0.53dB、ほかは 0.35dB 以下 |

MEG と並べて毎サンプル比べると、多くの形で −60〜−88dB。D.TURNTBL は、レコードの雑音を作る
`r = 16 × (0.90 × r + 0.71)` を 24bit で折り返す回し方（1 回ごとに 14 倍に広がる）を持ち、MEG の 42bit の整数と
float ではすぐに離れる。雑音の性質は同じで、書き出した音の帯の差は 2.4dB。

### 速さ

`blocktime … 512 10 1`、native の音源、交互に 2 回ずつ（Ryzen 7 9700X）。「マスタ」は SWP30 マスタの 1 サンプル。

| 曲 | 既定（MEG） | `--native-fx-full` |
|---|---|---|
| dense | マスタ 1380-1409ns（うち MEG 372-387）、1 ブロック 0.84ms | マスタ 1226ns、0.76ms |
| effects | マスタ 668-720ns（うち MEG 430-501）、0.51-0.53ms | マスタ 449-461ns、0.39-0.40ms |
| piano | マスタ 606ns（うち MEG 377-382）、0.44ms | マスタ 425ns、0.33-0.34ms |

口ごとの本体は、リバーブ約 40ns・コーラス約 50ns・バリエーション約 70ns・インサーション約 90ns。
送りが 0 で戻りも 1 LSB に満たないまま、遅延の窓 + 0.1 秒たった口は回さない（MEG の区画飛ばしと同じ決まり）。
係数と番地表は firmware が書き換えたときだけ読み直す。

### 残り

* インサーション 2-4 はスレーブの SWP30 の MEG のまま（軽量モードの対象はマスタの 4 つの口だけ）

### インサーションの乾いた音

インサーションを掛けたパートは、**乾いた音がミキサの乾いた出口（m20/m21）に出ない**。
音はいったん MEG の中を通り、戻ってきたものだけが出る。だから軽量モードで
「濡れた音しか出さない作り」（残響・初期反射・ディレイ）をインサーションに掛けると、
直の音が丸ごと消えていた（ディレイを掛けた音が、こだまだけになる）。

いまは `fx_slot::set_insertion()` を立てて、そのときだけ

```
出 = 濡れた音 × (Dry/Wet) + 乾いた音
```

とする。**乾いた音は Dry/Wet を下げても小さくならない**（実測。Dry/Wet=32 のディレイ 6 種で、
山の大きさが実機と 0.1dB しか違わない）。AMBIENCE（0x58）だけは乾いた音も割合で下がる。

### 機械まるごとの状態には入らない

軽量モードのディレイ・残響の中身（遅延線）は**状態に入れない**。全部で 5MB 近くあり、
DAW の企画ファイルが膨らむわりに、得られるのは「開き直したときに尾が切れない」だけだから
（MEG の側の尾は SWP30 のリバーブ RAM に入っているので、既定のモードでは切れない）。

代わりに、**状態を戻すときに軽量モードの中身を消す**（`load_state`）。
消さないと、前に鳴らしていた曲の尾が、戻した曲に混ざって出る。

インサーション 2-4 は**そのまま実機の音**（スレーブの SWP30 の MEG が作っていて、軽量モードでも
止めていない）。THRU を掛けて比べると rms 352.1 対 351.8 で一致する。

## 前の試作の速さ（2026-09-18。MEG を回さなくても 1 割ほど）

dense（16 パート・60 音）を 10 秒ぶん書き出したときの実時間（Ryzen 7 9700X、1 スレッド）。

| | 実時間 | 1 サンプルあたりの内訳 |
|---|---|---|
| 既定（MEG） | 2.03〜2.11 秒 | CPU 2298ns / SWP30 マスタ 1919ns（うち MEG 503ns） |
| `--native-fx-full` | 1.81〜1.82 秒 | CPU 2292ns / SWP30 マスタ 1315ns（MEG 0ns） |

**軽くなるのは 1 割ほど**（10〜14%）。理由は、重さの内訳がこうなっているから。

* SH-2（firmware）を動かすぶん … 2.3µs（全体の半分以上）
* SWP30 の声を作るぶん … 1.4µs
* **MEG（エフェクト）… 0.5µs**

つまり **エフェクトを C++ に置き換えても、消えるのは 0.5µs だけ**で、残りはそのまま残る。
「ネイティブ DSP なら桁違いに軽い」という話は、firmware ごとやめて XG の処理を全部書き直した場合の話で、
それはこのプロジェクトとは別の作りになる。

`--native-fx`（MEG も回す）は、MEG のぶんが残るので**既定より少し重い**。音の比べ用。

### 測るときの注意

per-sample の道に `static const bool x = std::getenv(...)` のような**関数内 static を置くと、それだけで
1 サンプルあたり 1µs ほど遅くなる**（呼ぶたびに初期化済みかを確かめる）。調べもの用の切り替えを
入れたまま測って、「軽量モードのほうが 4 割遅い」という逆の結果を出しかけた。切り替えは外して測ること。
