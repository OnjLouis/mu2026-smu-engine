# サンプリングの管理情報（firmware の表）

サンプリングの窓（`src/ui/sampling_editor.cpp`）は、パネルを通さず、firmware が CPU の DRAM に持つ表を
直に読み書きする。その表の形をここにまとめる。コードでは `src/sampling.h` が番地と形、
`src/sampling.cpp` が読み書き。

## 調べ方

`src/smpre.cpp`（`make build/smpre.exe`。`all` には入れない）でパネルを操作しながら、決めた所で
ワーク RAM・DRAM・サンプリング RAM を書き出し、前後を突き合わせた。録る・残す・2 つ目を録る・
EDIT → VOICE で割り当てる・Level と Pan を動かす、の各段で変わる所を見た。

確かめたこと:

* パネルで録った波形と、DRAM の 3 つの表（下）**だけ**を起動したての機械に写すと、firmware は
  SAMPLE の画面に `SMPL001 take001` を出し、試聴でき、REC は `Sp=002`・残り 46 秒から続く。
  ワーク RAM にあるサンプルの数や残りの容量の写しは、firmware が SAMPLING に入るたびに表から数え直す
* 音色の表の 1 つ目の要素にサンプルの番号を書いてプログラムチェンジを送るだけで、そのサンプルが鳴る
* `make test` の sampling（`src/samptest.cpp`）が、直に録って足したサンプルを firmware が一覧に出す・試聴できる・
  パネルの録音がその後ろに続く・音色として鳴る・窓の道（bridge → driver）で同じことができる、を毎回見る

## サンプリング RAM

4MB（0x100000 語）。1 語（32bit）に 16bit のサンプル 2 つ、下の 16bit が先。録音は A/D INPUT の値が
そのまま入る（16bit の 12000 を入れると 12000）。番地は「語」で数える。

## 表

番地は CPU から見た DRAM の番地。数はビッグエンディアン。

### 次に録る語（0x1070604）

`u32` 次の空きの語 | 0x01000000。サンプルの記録の表のすぐ後ろ。残りの容量は ここから 0x100000 語まで。

### サンプルの記録（0x106be04 から 36 バイト × 512）

サンプル n（1 から）は 0x106be04 + 36 × (n − 1)。

| 位置 | 中身 |
|---|---|
| +0 | `u16` 番号（n − 1） |
| +2 | 印。0x40 = 使っている |
| +4 | 00 00 00 00 |
| +8 | ff ff ff ff |
| +12 | `u32` サンプリング周波数（44100） |
| +16 | `u32` 開始の語 \| 0x01000000 |
| +20 | `u32` 終わりの語 \| 0x01000000 |
| +24 | 04 00 00 00 |
| +28 | 名前 8 文字（空白で埋める。録ると `take` + 番号 3 桁） |

### 鳴らすための表（0x103fa28 から 16 バイト × 512）

サンプル n は 0x103fa28 + 16 × (n − 1)。

| 位置 | 中身 |
|---|---|
| +0 | 00 3c 00 ff（0x3c は基準の鍵 60） |
| +4 | 上の 8bit: 0x40 = ループしない、0x00 = ループする。下の 24bit: 鳴り始めがループの頭より何サンプル手前か |
| +8 | `u32` ループの頭から鳴り終わりまでのサンプル数。**音源は「ループの頭 + この値」ちょうどで折り返す**（ループでなければそこで止まる） |
| +12 | `u32` ループの頭の語 \| 0x01000000 |

録った直後は +4 が 40 00 00 00、+12 が開始の語、+8 が (終わりの語 − 開始の語) × 2 − 4 で、全体を 1 度鳴らす（終わりの 4 サンプルは余白で、鳴らさない。サンプルの記録の +24 の 04 がその数）。
鳴り始めは「ループの頭 − +4 の下」、押しているあいだは +12 から +8 + 4 サンプルをくり返す。

EDIT → SAMPLE で確かめたこと（`smpre` で前後を突き合わせた）:

* Loop を on にすると +4 の上が 0x00 になり、サンプルの記録の +2 が 0x40 から 0x42 になる。Loop の値は off・on だけ
* End を 1 減らすと +8 が 1 減る
* Start を 1 増やすと +12 が 1 語進み、+4 の下が 1、+8 が 2 減る（ループの頭は語の境にしか置けないので、
  半語ぶんを +4 の下で戻す）。サンプルの記録の開始・終わりは変わらない
* firmware の Loop は始まりから終わりまで全体をくり返すだけ。+4 の下と +12 を書けば、途中からのループにもなる
* 鳴り始め・ループの頭・鳴り終わりを波形を切らずに決められる（サンプルの頭から S・L・E サンプルなら、
  +12 = 開始の語 + L / 2、+4 の下 = L − S、+8 = E − L。L は偶数。E はサンプルの終わりの 4 手前まで）

**ループの長さは +8 の値ちょうど**（2026-10-05）。4214 サンプルにサイン 25 周期を入れたサンプルで確かめた: +8 が 4210 だと出力の位相が
4210 サンプルおきに跳び（高さ 261.88Hz、ループの周期の側帯波 −32dB、音量が 2 割ゆれる）、4214 にすると跳ばない（261.628Hz、
側帯波 −82dB）。前は E を「+8 より 4 後ろ」と読んでいて、窓のループがどれも 4 サンプル短かった（作った波形は 0.1 秒ごとに
つなぎ目がずれ、「終点をループに合わせる」「ループ区間を探す」「クロスフェード」も 4 サンプルずれた所で合わせていた）。
いまは E が折り返す所そのもので、サンプルの終わりには余白 4 サンプルを残す（トリムも E の後ろに 4 サンプル残す）。
作った波形は、終わりに頭の 4 サンプルを足して登録する（折り返す所の次のサンプルも音源が読むので）。
  （440Hz の 0.5 秒と 660Hz の 0.5 秒をつないだサンプルで、ループの頭を 660Hz の頭にすると 660Hz だけが続く）

以前はこの表を 0x103fa20 + 16 × n の「長さ・開始・00 3c 00 ff 40 00 00 00」と読んでいた。区切りが 8 バイトずれていて、
後ろの 8 バイトは次のサンプルの頭だった。

### サンプル音色（0x1054e00 から 350 バイト × 256）

Bank# 0 の PGM001-128 が 0-127、Bank# 1 の PGM001-128 が 128-255（MIDI ではバンク MSB 16、LSB = Bank#）。

**形は ROM の XG の音色の記録とまったく同じ**: 頭の 12 バイト、84 バイトの要素が 4 つ、後ろに 2 バイト
（12 + 84 × 4 + 2 = 350）。ROM の音色は要素の数だけの長さで並ぶ（VOICES の 0x200EE0 から「14 + 84 × 要素の数」ずつ、
1635 件。`xg::voice_rom::wave_users`）が、サンプル音色はいつも 4 つぶんの場所を持つ。
要素の欄の意味は native エンジンの解析（[native-engine.md](native-engine.md)、`src/xg/native_voice.h`）がそのまま使える。

| 位置 | 中身 |
|---|---|
| +0 | 使う要素のビットマスク（01 = 1 つ目だけ、03 = 1・2 つ目、0f = 4 つとも）。ROM の音色の記録の先頭と同じ |
| +1 | 7f |
| +2 | 名前 8 文字（空白で埋める。既定は `Voice` + 番号 3 桁）。0 で埋めると LCD が CGRAM の 0 番の字を出す |
| +10 | 00 00 |
| +0x0c | 要素 1（84 バイト） |
| +0x60 | 要素 2 |
| +0xb4 | 要素 3 |
| +0x108 | 要素 4 |
| +0x15c | 2 バイト |

（2 つ目の要素は +0x60 から。+0 を 03 にすると 2 つ目の要素だけでも鳴る）。

内蔵ウェーブが使えることは s45e_mid さんが 2021 年に実機で見つけていた（サンプル音色の領域は SysEx でも書ける、
その波形の元に内蔵ウェーブの番号も指定できる）。

### サンプル音色を書く SysEx（機種 0x68）

ヤマハのパラメータチェンジの形で、機種 ID が **0x68**。機種 ID と番地の上の桁を総当たりで送り、
サンプル音色の表が変わるものを探して見つけた（ほかの機種 ID では 1 バイトも変わらない）。

```
F0 43 1n 68 AH AM AL <値> F7
  AH = 0x40 + 0x10 × Bank# + 区画（0 = 頭、1-4 = 要素 1-4）
  AM = PGM − 1（0-127）
```

| 区画 | AL | 書く所 |
|---|---|---|
| 頭 | 01 | +0 使う要素の印（0x0f より上は 0x0f に） |
| 頭 | 02 | +1 |
| 頭 | 03-0A | +2〜+9 名前 8 文字 |
| 要素 | 00 | 波形 [2] [3]（**値は 2 バイト**。要素 1 の [0] も 01 になる） |
| 要素 | 02-51 | [4]〜[83] |

AL 00・01 に 1 バイトの値を送っても何も変わらない。要素の AL 52・53 は次の要素の [0]・[1] にはみ出して書く
（firmware は範囲を見ていない）。

**要素 2 の波形（AH 0x42 / 0x52、AL 00）を受けると、firmware は頭の +0（使う要素の印）を書き換えてしまう**
（ほかの要素では起きない。値はそのときの中身で変わり、0x5b や 0xc3 になった。0x80 以上にもなるので、一括ダンプで
読み出すとその 1 バイトが SysEx を壊し、受け取った側では残りがプログラムチェンジのように見える）。音色をまるごと送るときは、要素を先に、頭を最後に送る（`sampling::voice_sysex`）。
こうして送った 334 通（3010 バイト）で、別の PGM に同じ記録ができる（要素 1 の [0] を除いて 350 バイトとも同じ。
`make test` の sampling）。サンプルの番号は、波形の 2 バイトに 7bit ずつしか入らないので、128 番より上のサンプルは
この SysEx では指せない（[3] の上の 1 ビットが落ちる）。

**実機でも確かめた**（2026-10-04、オーナーの MU2000EX）。この 334 通を実機の Bank 1 / PGM 128 に送り、一括ダンプの頼み
`F0 43 20 68 <AH> <AM> 00 F7`（AH は区画ごと、5 通）で読み出すと、エミュレータで同じことをしたときの返事と 402 バイトすべて
一致した（パラメータの頼み `F0 43 30 68 <AH> <AM> <AL> F7` にも答える）。内蔵ウェーブ 16 を鳴らす試しの音色を ch16 で鳴らして
S/PDIF で録ると、エミュレータの音と波形の相関 0.995、周波数帯ごとの割合は 0.1dB 以内、パンの左右差も同じだった。
実機が **GS モード**のときは、Bank MSB 16 を送ってもサンプル音色を選ばず、Bank 0 の同じ番号の音色を鳴らす（LSB も 0 にされる）。

**要素を 2 つ以上同時に鳴らせる**（実機で確かめた）。要素 1 に内蔵ウェーブ 16（左）、要素 2 に 39（右）を入れ、印を 03 にして
上の順（要素が先、頭が最後）で送ると、読み出した印は 03 のままで、2 つとも鳴り、エミュレータとの波形の相関は 0.998〜0.999 だった。
s45e_mid さんは 2021 年に「印は最下位ビットしか見てくれない」「一括ダンプで受け取るとこの所だけ値が化ける」と書いていたが、
これは印を先に送ってから要素を書いたため。同じ並び（頭が先）で送ると、実機でもエミュレータでも印は 0xc3 に化けた。
内蔵ウェーブは、XG の音色で 2 要素の音色にしか使われていない組も、1 要素の音色の組と同じに鳴る（エミュレータで 503 組すべて、
実機で W39 を確かめた）。

### 波形とサンプルを書く SysEx（機種 0x68 の一括ダンプ）

同じ機種 0x68 の**一括ダンプ**で、サンプリング RAM の波形とサンプルの表も読み書きできる。並びは shingo45endo さんの
[M2A to SMF Converter](https://github.com/shingo45endo/midiana)（MIT）で知り、firmware 自身のダンプ（頼みは
`F0 43 20 68 AH AM AL F7`）と突き合わせて確かめた。こちらの実装は `sampling::memory_sysex`。

```
F0 43 0n 68 <数の上> <数の下> AH AM AL <データ…> <検査の和> F7
  数 = データのバイト数（7bit × 2）。検査の和 = 数・番地・データと足して下 7bit が 0 になる値
```

| AH AM AL | データ | 中身 |
|---|---|---|
| 00 00 7F | （パラメータチェンジ `F0 43 1n 68 00 00 7F 00 F7`） | サンプリングの中身を全部消す。この後 1 秒待つ |
| 00 00 00 | 4 | 波形を書く位置。**64 バイトの塊の番号**（7bit × 4、上から）。頼んでも返事は無い |
| 00 01 00 | 74 | 波形 64 バイト。書く位置は 1 通ごとに 1 つ進む |
| 00 00 10 | 5 | 次に録る語（0x1070604 の下 24bit。7bit × 5、上から） |
| 10+(n>>7) n&7F 00 | 22 | サンプル n（0 から）の記録 |
| 同 70 | 8 | サンプルの名前 |
| 同 20 | 24 | 鳴らすための表 |

**波形の詰め方**（64 → 74 バイト）: 7 バイトずつ、下 7bit を 7 つ並べ、その後ろに上の 1bit を 7 つ集めた 1 バイト
（先のバイトが bit 6）。これを 9 組（63 バイト）、最後の 1 バイトは下 7bit・上 1bit の 2 バイト。波形は 16bit の
**上のバイトが先**（サンプリング RAM の中とは逆）。

**サンプルの記録**（22 バイト）: 記録の +2（印）、+3、00、ステレオの相手の番号（7bit × 2。無しは 7F 7F。記録の中では +4 に
相手の記録の番地で入っている）、周波数（7bit × 5）、開始の語（× 5）、終わりの語（× 5）、+25、+24。

**鳴らすための表**（24 バイト）: 表の +0、+3 の下 7bit、+1、印（bit 0 = +2 の符号、bit 6 = +3 の上の 1bit）、+2 の大きさ、
+12 の下 24bit（× 5）、+9〜+11（× 5）、+5〜+7（× 5）、+8 の上 1bit、+8 の下 7bit、+4 の上 1bit、+4 の下 7bit。
受け取った firmware は +3 を下 7bit だけで書く（録ったときの ff が 7f になる）。鳴る音は変わらない。

サンプルを 2 つ（片方はループと鳴らす範囲つき）と音色を入れた機械に、そこから作った 569 通（22,434 バイト）を送ると、
1 通目で一覧が空になり、残りで波形・記録・表（+3 を除く）・音色（要素の [0] を除く）が 1 バイトも違わずに戻り、
戻した音色が同じ大きさで鳴る（`make test` の sampling）。

**波形を読む**ときは、書く位置（`00 00 00`）を先に送り、頼み `F0 43 20 68 00 01 00 F7` をくり返す。読む位置は書く位置と
同じもので、1 通返すごとに 1 塊進む（番地では選べない。AL を 01 以上にしても返事は無く、位置だけ進む）。
全部を消す 1 通は表を消すだけで、サンプリング RAM の中身は残る。

**実機でも確かめた**（2026-10-04、オーナーの MU2000EX、USB）。作ったノコギリ（ループ）とランプ（ループと鳴らす範囲つき）、
Bank 0 / PGM001 の音色を入れた 569 通（22,434 バイト）を、1 通目の後 1.5 秒、あとは 30ms おきに送った。読み戻すと、
空き・サンプル 32 個ぶんの記録/名前/表・音色 256 個の頭（353 通）、音色の 5 区画、波形の使っている 226 塊が、同じものを
受けたエミュレーターの返事と 1 バイトも違わなかった。ch16 で鳴らして S/PDIF で録ると、鍵 60 が 261.7Hz、鍵 72 が 523.3Hz。
その前に実機の中身（サンプル 3 つ 13 秒ぶん = 17,950 塊と音色）を上の頼みで読み出して控え、試しの後に戻した。

**実機は長く送ると通を取りこぼす。** 控えの 17,950 通を 30ms おきに送り直したところ、読み戻すと 17 通（およそ 1000 通に 1 通）が
入っておらず、書く位置は受けた通の数で進むので、取りこぼした所から後ろが 1 塊（32 サンプル）ずつ前へずれていた
（上の 569 通が一致したのは、量が少なくて当たらなかっただけ）。40ms おきにしても同じ割合で落ちる。直すには、128 塊ごとに
書く位置を入れてから波形を送り、同じ区間を読み戻して比べ、違う区間だけ送り直す。これを 6 巡して（133 → 19 → 4 → 2 → 1 → 1 → 0 区間）
全部が控えと一致した。`sampling::memory_sysex` は 64 塊ごとに書く位置を入れ直すので、取りこぼしてもずれはその区間で止まるが、
落ちた 1 塊は入らないままになる。**読み戻して確かめない送りっぱなしでは、長い波形は化けることがある。**

**エミュレーターに読み込むとき**（窓の「SysEx を読み込む」、`mu2000::sampling_load_sysex`）は、MIDI の速さで待たない。
「全部を消す」の 1 通だけを firmware に送って消させ（消した後の DRAM は起動したてと 1 バイトも違わない）、波形・次に録る語・
サンプルの記録・名前・鳴らすための表は、firmware が受けたときと同じ結果を直に書く。ほかの通（音色など）は firmware が受ける。
MIDI で全部送ったときと同じ表・波形・音色になる（`make test` の sampling）。実機から読み出した控え（17,961 通）を
そのまま読み込むと、サンプル 3 つと、ループ・音色への割り当てまで実機と同じに入った。
